# ZOMZEY Homepage — Content Map

**Version:** 0.1  
**Purpose:** preserve useful functionality while giving the homepage a clearer and more distinctive hierarchy.

## Existing homepage inventory

The current homepage exposes the Opportunity Network proposition; “Get a service” and “Give a service”; broad category navigation; directory search and filters; two step-by-step service journeys; a member-location/map area; member videos and a video competition; use-case links; tools; account access; and support/footer navigation.

Do not remove an item simply because it complicates the visual design. Decide whether it should remain prominent, move into a menu, become a compact resource link, or route to an existing page.

## Proposed section order

| Order | Section | Purpose | Notes |
|---|---|---|---|
| 01 | Header and navigation | Brand recognition, primary routes, account access | Reduce visible clutter; group the long category taxonomy under a clear discovery menu. Keep key destinations reachable. |
| 02 | Hero: The Opportunity Network | Explain the product and establish a visual signature | Use the dot-matrix identity as a signal/network motif. Keep copy concise and expose both main journeys. |
| 03 | Two primary pathways | Help visitors choose “Get a service” or “Give a service” | Distinct user goals, expressed as related visual choices. |
| 04 | Explore the network | Support discovery across creators, shops, communities, venues, events, musicians, agencies, authors, and related categories | Make categories scannable; avoid a long unstructured list. |
| 05 | Search and filters | Help users narrow discovery | Keep controls readable on mobile. Local demo data must be labelled; do not imply sample results are live. |
| 06 | How it works | Explain both service journeys | Preserve both flows. Consider an accessible interactive stepper if it improves clarity. |
| 07 | Network / member map | Show breadth and geographic discovery | Confirm data source before promising live member pins. Otherwise use an explicitly illustrative network graphic. |
| 08 | Member stories and video | Show real use cases and human credibility | Use only approved/available assets, provide accessible controls, and avoid autoplay with sound. Preserve the video-competition link if still relevant. |
| 09 | Use cases and tools | Surface promotion needs and existing calculators/resources | Use a compact resource cluster; avoid duplicating the mega-menu. |
| 10 | Final conversion and footer | Provide a next step and retain support/legal routes | Include sign-up/sign-in, support, About, pricing, tools, and key destinations as appropriate. |

## Navigation destinations to preserve or re-home

### Main destinations
- About
- Pioneers and relevant categories
- Influencers / creators and relevant channels
- Hubs and relevant types
- Agencies
- Pricing
- Tools
- Sign in / Sign up

### Supporting destinations
- Developers
- Support Hub
- Affiliate information
- ZOMZEY Beacon and other tools/resources
- Terms, help, and contact details where appropriate

The redesigned presentation may simplify the navigation, but the content audit must record where each important route ends up.

## Interaction inventory

| Element | Expected behavior | Static-demo boundary |
|---|---|---|
| Desktop navigation | Clear links and accessible menu states | Use verified platform destinations where known. |
| Mobile navigation | Open/close, Escape to close, sensible focus and scroll behavior | Test at narrow widths. |
| Main pathway CTAs | Route toward the corresponding ZOMZEY journey | Do not imitate registration or payment flows. |
| Category cards | Navigate to a category or open exploration | Verify routes and label demo-only paths. |
| Search/filter | Filter demo entries or navigate to real results | Clearly disclose local sample data. |
| How-it-works steps | Switch active step by pointer and keyboard | Provide accessible state and readable fallback. |
| Network/map graphic | Communicate connections or verified location discovery | No invented live pins, counts, or profiles. |
| Video cards | Open or play intended public/approved content | Avoid autoplay with sound; consider captions and loading. |
| Account actions | Open the real ZOMZEY account flow | Never collect credentials in the static prototype. |
| Tool/resource links | Open existing pages | Verify target URLs before final submission. |

## Content principles

- Use English in the interface to match the existing website.
- Do not invent member counts, ratings, transactions, or performance statistics.
- Do not promise features unsupported by the live service.
- Use clear link text and visible keyboard focus.
- Recheck map, video, testimonial, and calculator assets during implementation rather than assuming remote resources will always remain available.
